FileMaker analysis tool

Connect the dots in your FileMaker solution

nuthatch is a static-analysis tool for FileMaker “Save a Copy as XML” exports. Load one file or a whole multi-file solution and explore its structure, dependencies, call chains, and maintenance risks. Find broken references, unused objects, and mistakes in scripts, trace where a value list, custom function, table occurrence, or any other object is used, and compare two versions side by side. Everything is parsed locally, in your browser or the desktop app. Nothing is uploaded.

Try it in your browser View on GitHub

Browse every object

Pick an object type in the navigator and open any table, field, layout, or script. Each one shows what it references, what references it, and its call chain, with broken references flagged where they occur.

Start from what's wrong

The report card counts broken references, accounts without a password, scripts flagged by the script checks, unstored or deep calculations, and unreferenced objects. Click any number to see the objects behind it.

Find what's really unused

The report card counts unreferenced objects, and also the objects used only by them, since those are dead too. Some objects are used where the export can't see: by a server schedule, the Data API, a file that isn't loaded, or a call by name. Mark them as used, or as kept on purpose, and they drop off the unused lists along with everything they use. Marks are saved with the project, so they still apply after you export again.

Catch mistakes in your scripts

Script checks go through every script step by step, like a linter for FileMaker, and flag what will go wrong: steps that never run, a $variable that's read but never set, a field that's set, inserted into or read from a table occurrence that isn't related to the layout the script is on, a parameter key that no caller passes, and a script result that's read before any script has run or that the called script never returns. Flagged steps are marked in the script, and the Script checks filter lists every script with a finding. Script checks are in preview.

Know what breaks before you change it

Open the Used by tab before you rename or delete something. It lists every field, layout, button, and script that depends on the object, across all loaded files. Uses shows the other direction, and a script's Calls tab shows its call chain.

Jump anywhere with ⌘K

Search names, calculations, and script steps across every loaded file. Filters like type:script, is:unreferenced, or refs>20 narrow it down.

Put two objects side by side

⇧-click a search result or a reference to open it in a second pane. Collapse the navigator when you need the room, like here, comparing two versions of a custom function.

See what changed

Save an analysis, export again later, and compare. Renamed objects stay matched, and changed scripts and calculations show a line-by-line diff.

See how your tables connect

The ERD tab draws the relationship graph with each table occurrence in its FileMaker color. Color the lines by cascade delete, record creation, or sorting, click a box to highlight the other occurrences of its table, and double-click it to show its fields.

Export for AI

Give your AI assistant the answers, not the XML

Choose Export for AI on any saved analysis, or run the command-line tool. nuthatch writes a compact index of your solution into your project folder, with every reference already resolved and what the script checks found, so your assistant looks answers up instead of searching the raw XML. That saves tokens, makes each lookup faster, and gets you better answers, because the assistant no longer has to work out from the XML what refers to what.

Command line

Export from the terminal

The standalone nuthatch command runs the same parser without opening the app, and it doesn't need Node installed. Re-export after every change to your solution, or add it to a script. 

nuthatch export-ai Solution.xml
Exported 21867 objects and 46949 references
to ~/my-project/nuthatch
